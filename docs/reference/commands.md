# Commands

Every command and its options, as `flowreel <command> <action> --help` prints them.
This page is generated by `tools/reference.py` from the commands' own help, so it
is always the installed version's. How the commands are used together, with
examples and output, is in the guide's [commands](../guide/commands.md) page.

## `project`

Make a project folder, see what it holds, clean what it made.

### `flowreel project init`

```text
usage: flowreel project init [-h] [-o DIR] [--force] [--import KIND:PATH] [--tag TAG]

Make the project folder DIR: shots/, panels/, layouts/, assets/ and data/,
flowreel.yml, film.yml and cameras.yml at the root (film.yml and cameras.yml
are kept if they exist), and a .gitignore for frames/, clips/, .flowreel/ and
data/.

A case comes in as a tag: --import KIND:PATH --tag TAG does what data import
does, and fits the first view of cameras.yml to the case.

options:
  -h, --help          show this help message and exit
  -o DIR, --out DIR   project folder (default the current one)
  --force             overwrite flowreel.yml if it exists
  --import KIND:PATH  import a case as a tag as well (plt:PATH, vtk:PATH), as data
                      import does; give --tag
  --tag TAG           the tag of --import

examples:
  flowreel project init                             the folders and first files, here
  flowreel project init -o carve --force            overwrite flowreel.yml
  flowreel project init --import plt:/scratch/run/binary --tag bare
                                                    the folders, and the case as a tag
  flowreel project init --import vtk:/scratch/run --tag run -o films/afms
```

### `flowreel project info`

```text
usage: flowreel project info [-h] [DIR]

Print the project's tags, the sources its shots read, every shot file with the
frames drawn for it, the views and tracks of cameras.yml, the film's scenes,
and the size of frames/, clips/ and .flowreel/. Files that do not load are
listed with their error. Nothing is changed.

positional arguments:
  DIR         a folder in the project (default: use project:DIR, else here)

options:
  -h, --help  show this help message and exit

examples:
  flowreel project info                             the project of this folder
  flowreel project info films/afms
```

### `flowreel project clean`

```text
usage: flowreel project clean [-h] [--cache] [--frames] [--clips] [--dry-run] [DIR]

Remove generated output of the project: --cache (.flowreel/cache/, the default
when nothing is named), --frames (frames/) and --clips (clips/). Files written
by hand, the data, and the measured frame costs and job records in .flowreel/
are never removed. A folder that is a link is skipped.

positional arguments:
  DIR         a folder in the project (default: use project:DIR, else here)

options:
  -h, --help  show this help message and exit
  --cache     the caches, .flowreel/cache/
  --frames    every frame folder, frames/
  --clips     the finished clips, clips/
  --dry-run   say what would be removed, and its size; remove nothing

examples:
  flowreel project clean                            the caches (.flowreel/cache/)
  flowreel project clean --frames --dry-run         what removing the frames would free
  flowreel project clean --frames --clips           frames and finished clips
```

## `data`

A project's data by tag: each case's domain.yml.

### `flowreel data import`

```text
usage: flowreel data import [-h] [--path PATH] --tag TAG [--body NAME=FILE]
                            [--flow FILE] [--name FUNCTION] [--param KEY=VALUE]
                            [--group N=BODY] [--copy] [--yes] [--force]
                            {plt,vtk,geometry,history}

history: link a FlexFlow case's othd_files/ and oisd_files/ into the tag,
convert each group (othId, osgId) once to CSV under data/TAG/series/, restarts
resolved (a later run wins), and declare it under its body in domain.yml.
Otherwise: link the folder a case's files are in under data/TAG/ (plt or vtk;
geometry links nothing) and write data/TAG/domain.yml with what was measured:
the reader's options, each wall zone as a body with its axis and diameter, and
the steps, zones, fields and bounds; the units are left to fill in. --copy
copies the files instead, after saying their size. A tag holding a case
already is refused unless --force, which replaces the link and keeps the edits
of domain.yml.

positional arguments:
  {plt,vtk,geometry,history}
                        what the case is; history: its OTHD and OISD files, into a tag
                        already imported

options:
  -h, --help            show this help message and exit
  --path PATH           the folder the files are in
  --tag TAG             the tag: letters, digits, - and _
  --body NAME=FILE      vtk: a body's surface file, by name (repeat for each)
  --flow FILE           vtk: the flow within PATH (default its one .pvd)
  --name FUNCTION       geometry: the body made in code
  --param KEY=VALUE     geometry: a parameter of the body (repeat)
  --group N=BODY        history: the body group N is declared under (repeat; default
                        the one body, when the files hold one group)
  --copy                copy the files instead of linking
  --yes                 copy even above 5 GB
  --force               replace the tag's link (domain.yml keeps its edits)

examples:
  flowreel data import plt --path /scratch/run/binary --tag bare
                                            link the folder of PLT files as data/bare/plt
  flowreel data import vtk --path runs/cyl35 --tag cyl35 --body cylinder=runs/cyl35/cylinder.vtp
  flowreel data import plt --path small_case --tag test --copy
                                            copy instead of link (asks --yes above 5 GB)
  flowreel data import geometry --name grooved_cylinder --tag carve --param grooves=4
  flowreel data import plt --path /scratch/run2/binary --tag bare --force
                                            point bare at another folder; edits kept
  flowreel data import history --path /scratch/run --tag bare
                                            othd_files/ and oisd_files/, a CSV per group
  flowreel data import history --path /scratch/run --tag two --group 0=riser --group 1=ball
```

## `shot`

Render, preview and measure shots.

### `flowreel shot render`

```text
usage: flowreel shot render [-h] [--frames SPEC] [--scale S] [--size W H] [--force]
                            [--save-vtp DIR] [-j N] [--threads T]
                            [--backend {auto,osmesa,egl,x}] [--no-memory-check]
                            [-o DIR] [--slurm FILE] [--submit] [--cluster NAME]
                            [--partition NAME] [--time T] [--mem SIZE] [--cpus N]
                            [--after JOBID] [--max-running N] [--missing]
                            [shot]

Render a shot's frames to OUT/<shot>/frame_00000.png. Frames whose key did not
change are skipped; a draft (--scale, --size) goes to OUT/<shot>@<W>x<H>/.

positional arguments:
  shot                  shot file (default: the shot set with use shot:FILE)

options:
  -h, --help            show this help message and exit
  --frames SPEC         frames to draw: A, A:B (both included), A:B:E, or a comma list
  --scale S             draw at the shot's size times S (a draft), e.g. 0.5
  --size W H            draw at W x H pixels (a draft)
  --force               draw the frames even when their key did not change
  --save-vtp DIR        instead of drawing frames, save the scene's surfaces at each
                        step the frames show into DIR, to open with 'camera edit --vtp
                        DIR' on a machine with a display
  -j N, --jobs N        frames drawn at once, each in its own process (default 1)
  --threads T           threads per job (default: min(4, cores / jobs))
  --backend {auto,osmesa,egl,x}
                        off-screen OpenGL: auto (OSMesa, else EGL), osmesa, egl or x
  --no-memory-check     draw even if the jobs look too big for the free memory
  -o DIR, --out DIR     folder of the frame folders (default frames/ at the project
                        root)

Slurm (run as a job on a cluster; docs/guide/making/slurm.md):
  --slurm FILE          write a Slurm job script to FILE instead of running here
  --submit              submit the job with sbatch (the script goes to jobs/NAME.sh
                        unless --slurm FILE)
  --cluster NAME        the cluster (default: FLOWREEL_CLUSTER, or this host's)
  --partition NAME      the partition (default: the shortest that takes the job)
  --time T              time a job may run: 90m, 3h, 1-12:00:00 (default: estimated)
  --mem SIZE            memory of a job: 32G, 500M (default: worked out)
  --cpus N              cores of a job (default: 16 for a render, 4 otherwise)
  --after JOBID         start only when job JOBID ended well (may be repeated)
  --max-running N       at most N tasks of the render at once, so it takes part of a
                        node
  --missing             plan tasks only for frames not drawn yet

examples:
  flowreel shot render carve.yml -j 16            every frame, 16 at a time
  flowreel shot render carve.yml --frames 0:48:4  frames 0, 4, ... 48
  flowreel shot render carve.yml --scale 0.5      a half-size draft, in frames/carve@960x540/
  flowreel shot render carve.yml --force          draw again even if nothing changed
  flowreel shot render carve.yml --submit         as a Slurm job array, sized from a
                                                  measured frame (docs/guide/making/slurm.md)
  flowreel shot render carve.yml --slurm carve.sh --max-running 2   write the script only
  flowreel shot render carve.yml --submit --missing                 only frames not drawn
```

### `flowreel shot preview`

```text
usage: flowreel shot preview [-h] [--every N] [--scale S] [--size W H] [-j N]
                             [--threads T] [--backend {auto,osmesa,egl,x}]
                             [--no-memory-check] [-o DIR]
                             [shot]

Draw every N-th frame (and the last) at a small size, into
OUT/<shot>@<W>x<H>/: a quick look at the timing before a full render.

positional arguments:

options:

  --scale S             draw at the shot's size times S (a draft), e.g. 0.5
  --size W H            draw at W x H pixels (a draft)
  -j N, --jobs N        frames drawn at once, each in its own process (default 1)
  --threads T           threads per job (default: min(4, cores / jobs))
  --backend {auto,osmesa,egl,x}
                        off-screen OpenGL: auto (OSMesa, else EGL), osmesa, egl or x
  --no-memory-check     draw even if the jobs look too big for the free memory
  -o DIR, --out DIR     folder of the frame folders (default frames/ at the project
                        root)

examples:
  flowreel shot preview carve.yml                 every 10th frame at a quarter size
  flowreel shot preview carve.yml --every 4 --scale 0.5
```

### `flowreel shot memory`

```text
usage: flowreel shot memory [-h] [--frame N] [--scale S] [--size W H] [--threads T]
                            [--backend {auto,osmesa,egl,x}] [-o DIR]
                            [shot]

Draw one frame in a fresh process, as render does, and report its peak memory,
the free memory and the number of jobs that fit.

positional arguments:
  shot                  shot file (default: the shot set with use shot:FILE)

options:
  -h, --help            show this help message and exit
  --frame N             frame to measure (default 0: in a frozen shot, the one that
                        contours)
  --scale S             draw at the shot's size times S (a draft), e.g. 0.5
  --size W H            draw at W x H pixels (a draft)
  --threads T           threads per job; caps the suggested jobs at cores / T
  --backend {auto,osmesa,egl,x}
                        off-screen OpenGL: auto, osmesa, egl or x
  -o DIR, --out DIR     folder of the frame folders, whose measurement sizes Slurm
                        jobs (default frames/ at the project root)

examples:
  flowreel shot memory carve.yml                  measure frame 0, suggest -j
  flowreel shot memory carve.yml --frame 200 --threads 2
```

## `camera`

Pick, make, import and check camera views and tracks.

### `flowreel camera edit`

```text
usage: flowreel camera edit [-h] --track NAME [--frames N] [--vtp DIR] [--film FILE]
                            [--spline] [--size W H] [-c FILE]
                            [shot]

Open the camera editor on the shot's scene: move the camera, set the Frame
slider, press s to save the view as a key of the track. Every change is
written to cameras.yml at once.

positional arguments:
  shot                  shot file (default: the shot set with use shot:FILE)

options:
  -h, --help            show this help message and exit
  --track NAME          the track to make or extend
  --frames N            the track's length (default: the shot's frames; needed with
                        --vtp and no shot)
  --vtp DIR             open surfaces saved by 'shot render --save-vtp DIR' instead of
                        the data
  --film FILE           mark the points in the model that this film's captions point
                        at
  --spline              write the track with path: spline
  --size W H            the window's size (default 1280 720)
  -c FILE, --cameras FILE
                        cameras.yml to read and write (default: the project's, at its
                        root)

examples:
  flowreel camera edit wake.yml --track approach     a window on the shot's first step
  flowreel camera edit wake.yml --track approach --film film.yml   with the points boxes follow
  flowreel camera edit --vtp wake_vtp --track approach --frames 240 -c cameras.yml
                                                     away from the data (shot render --save-vtp)

keys: s save view, u undo, r replace nearest, p play, n next step
```

### `flowreel camera orbit`

```text
usage: flowreel camera orbit [-h] --radius R --frames N [--target X Y Z] [--body NAME]
                             [--station S] [--step N] [--shot FILE] [--azimuth A]
                             [--span S] [--elevation E [E ...]] [--axis x|y|z]
                             [--up X Y Z] [--lead L] [--view-angle DEG] [--ease E]
                             [-c FILE]
                             NAME

Write views and a track that circle a target: a point (--target), or a body's
centre at a station along its axis (--body, --station, with the shot's
source). Angles in degrees.

positional arguments:
  NAME                  the track's name (views NAME_00, NAME_01, ...)

options:
  -h, --help            show this help message and exit
  --radius R            the camera's distance from the target
  --frames N            the track's length
  --target X Y Z        a point
  --body NAME           a body of the shot's source ('' for the one)
  --station S           where along the body's axis
  --step N              the body at this step (default the first)
  --shot FILE           the shot whose source has the body
  --azimuth A           where it starts (0)
  --span S              degrees turned, + anticlockwise seen from the axis tip (360)
  --elevation E [E ...]
                        above the plane across the axis: one angle, or from and to (0)
  --axis x|y|z          turn about this axis (default y, or with --station the body's
                        axis; the station is always along the body's axis)
  --up X Y Z            the camera's up (default the axis)
  --lead L              focal point moved this far along the axis (0)
  --view-angle DEG      (30)
  --ease E              over the whole turn (smooth)
  -c FILE, --cameras FILE
                        cameras.yml to read and write (default: the project's, at its
                        root)

examples:
  flowreel camera orbit turn --target 6 0 9.5 --radius 12 --frames 240
  flowreel camera orbit turn --target 6 0 9.5 --radius 12 --frames 240 --azimuth -30 \
      --span 120 --elevation 10 35
  flowreel camera orbit riser_turn --shot riser.yml --body riser --station 250 \
      --radius 8 --frames 240 --span 180 --up 0 1 0 --lead 2
```

## `panel`

Draw a panel's frames, or start a panel file.

### `flowreel panel draw`

```text
usage: flowreel panel draw [-h] [--frames SPEC] [--force] [-j N] [-o DIR]
                           [--slurm FILE] [--submit] [--cluster NAME]
                           [--partition NAME] [--time T] [--mem SIZE] [--cpus N]
                           [--after JOBID]
                           panel

Draw the frames of a panel file into OUT/<panel>/frame_00000.png, frame i at
the panel's time i. Frames whose key did not change are skipped. With -j N the
frames are cut into N runs of consecutive frames, each drawn by its own
process. A panel box of a film of scenes needs no draw: the build draws it at
the box's size.

positional arguments:
  panel              the panel file

options:
  -h, --help         show this help message and exit
  --frames SPEC      frames to draw: A, A:B (both included), A:B:E, or a comma list
  --force            draw the frames even when their key did not change
  -j N, --jobs N     processes drawing at once (default 1)
  -o DIR, --out DIR  folder of the frame folders (default frames/ at the project root)

Slurm (run as a job on a cluster; docs/guide/making/slurm.md):
  --slurm FILE       write a Slurm job script to FILE instead of running here
  --submit           submit the job with sbatch (the script goes to jobs/NAME.sh
                     unless --slurm FILE)
  --cluster NAME     the cluster (default: FLOWREEL_CLUSTER, or this host's)
  --partition NAME   the partition (default: the shortest that takes the job)
  --time T           time a job may run: 90m, 3h, 1-12:00:00 (default: estimated)
  --mem SIZE         memory of a job: 32G, 500M (default: worked out)
  --cpus N           cores of a job (default: 16 for a render, 4 otherwise)
  --after JOBID      start only when job JOBID ended well (may be repeated)

examples:
  flowreel panel draw panels/lift.yml              every frame, into frames/lift/
  flowreel panel draw panels/lift.yml -j 8         eight runs of frames at once
  flowreel panel draw panels/lift.yml --frames 0:10 --force
```

### `flowreel panel template`

```text
usage: flowreel panel template [-h]
```

## `film`

Build a film and check it.

### `flowreel film build`

```text
usage: flowreel film build [-h] [--only SCENE] [--mute] [--force] [--preview HEIGHT]
                           [--crf N] [--watch] [--clips DIR] [--slurm FILE] [--submit]
                           [--cluster NAME] [--partition NAME] [--time T] [--mem SIZE]
                           [--cpus N] [--after JOBID]
                           [FILM]

Build every scene's finished clip (clips whose key did not change are kept),
join them into the film's output with its sound and chapters, and write
film.srt and chapters.txt beside it. Prints each scene's planned and measured
length.

positional arguments:
  FILM              the film file (default: film.yml of the project set with use
                    project:DIR, else ./film.yml)

options:
  -h, --help        show this help message and exit
  --only SCENE      build this scene's finished clip alone, as film_SCENE.mp4, silent
  --mute            build the film without its sound
  --force           build every clip again, even when its key did not change
  --preview HEIGHT  also write film_<HEIGHT>p.mp4, scaled to HEIGHT pixels (even)
  --crf N           quality of the preview copy, 0 to 51, lower is better (default 28)
  --watch           build, then build again each time a file the film may be made from
                    changes, until Ctrl-C
  --clips DIR       folder of the clips (default clips/ at the project root)

Slurm (run as a job on a cluster; docs/guide/making/slurm.md):
  --slurm FILE      write a Slurm job script to FILE instead of running here
  --submit          submit the job with sbatch (the script goes to jobs/NAME.sh unless
                    --slurm FILE)
  --cluster NAME    the cluster (default: FLOWREEL_CLUSTER, or this host's)
  --partition NAME  the partition (default: the shortest that takes the job)
  --time T          time a job may run: 90m, 3h, 1-12:00:00 (default: estimated)
  --mem SIZE        memory of a job: 32G, 500M (default: worked out)
  --cpus N          cores of a job (default: 16 for a render, 4 otherwise)
  --after JOBID     start only when job JOBID ended well (may be repeated)

examples:
  flowreel film build                        the film, from ./film.yml
  flowreel film build talk.yml --mute        without its sound
  flowreel film build --preview 480          and film_480p.mp4, to send to someone
  flowreel film build --preview 720 --crf 23 a better preview copy
  flowreel film build --only compare         one scene alone, as film_compare.mp4
  flowreel film build --force                build every clip again
  flowreel film build --watch --preview 540  again on each change, until Ctrl-C
  flowreel film build --submit --after 1312  as a Slurm job, after the composes
```
